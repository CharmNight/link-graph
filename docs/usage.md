# 使用说明

## 目标读者

这份文档主要面向插件使用者，介绍如何在 IDE 中打开 Link Graph、理解三种视图，并使用 Mermaid、讲解、问答、草稿、实现建议和代码 diff 等主要功能。

## 打开方式

可以通过以下入口打开 Link Graph：

- 在编辑器中右键，使用链路图相关动作
- 通过工具菜单中的链路图分组打开
- 直接打开右侧工具窗口中的链路图面板

如果当前主体可被识别，插件会围绕当前方法或当前资源加载图数据。

## 界面概览

Link Graph 的工作台通常包含以下区域：

- 顶部任务栏
  - 展示当前目标、`理解链路 / 核验证据 / 风险问答 / 草稿确认 / 代码落地` 五阶段流程，以及导入或导出 Mermaid、对比代码、同步预览、打开设置等全局动作。
- 左侧链路大纲
  - 从入口、关键路径、资源证据、风险线索和草稿影响定位当前链路。
- 中间图谱舞台
  - 展示事实图、流程图或资源关系视图；图谱模式与右侧阶段互不绑定。
- 右侧阶段工作台
  - 阶段短标签为 `理解 / 证据 / 问答 / 草稿 / 代码`。
  - `理解` 展示稳定步骤。
  - `证据` 展示选中节点、证据强度、证据缺口、源码片段、风险线程和候选变更。
  - `问答` 展示多轮聊天、待确认变更和风险线索。
  - `草稿` 展示已确认变更、业务前后对比和实现建议，并作为后续生成唯一依据。
  - `代码` 展示文件级代码 diff、写回结果和目标文件入口。
- 底部变更托盘
  - 汇总候选变更、已确认草稿、阻塞风险、diff 状态和写回入口。

## 三种视图怎么用

### 事实图

适合回答“当前方法和上下游依赖是什么”。

推荐用法：

- 从当前方法打开事实图，先看主体与上下游关系
- 通过节点选择、展开和折叠控制阅读范围
- 当你需要定位某个调用链节点时，直接从这里跳回源码

### 流程图

适合回答“当前方法内部的执行步骤和控制流是什么”。

推荐用法：

- 在事实图确认主体后切到流程图
- 用它阅读主要步骤、分支、合流和终止路径
- 当你关注方法内部条件分支或关键流程节点时，优先看流程图

### 资源关系视图

适合回答“代码和资源文件之间有什么连接”。

推荐用法：

- 查看代码与 XML、SQL、配置、文档等资源之间的关系
- 当你怀疑链路跨越配置、Mapper、SQL 或资源文件时，切到这一视图核对

## Mermaid 相关功能

### 导入 Mermaid

适用场景：

- 已经有一份设计草图，希望和当前工作图对照
- 希望从 Mermaid 文本开始补图或做同步分析

使用方式：

1. 点击工具栏或菜单中的“导入 Mermaid”
2. 粘贴 Mermaid 文本
3. 确认导入结果和校验问题

### 导出 Mermaid

适用场景：

- 想把当前图分享给他人
- 想作为设计评审或后续修改的基础文本

使用方式：

1. 点击“导出 Mermaid”
2. 查看生成结果
3. 复制或保存导出的 Mermaid 内容

### 差异与同步预览

当你已经导入 Mermaid，并且当前工作图也存在时，可以继续查看差异和同步预览。这个流程适合用来回答：

- 设计图和现状代码图差在哪
- 如果按设计调整，预计会改哪些节点或关系

## 讲解、问答、草稿、实现建议和代码 diff

### 讲解

适用场景：

- 需要快速理解当前链路
- 希望按稳定步骤阅读，而不是看一段总结
- 希望围绕某一步继续追问或下钻到被调方法

常见使用方式：

1. 打开 `讲解` Tab
2. 在左侧步骤列表中选择当前关注步骤
3. 在右侧查看步骤说明、证据和可追问问题
4. 需要沉淀阅读结论时，点击“添加到草稿”

### 问答

适用场景：

- 希望直接解释“是什么、如何触发、谁调用、入口在哪”
- 希望找遗漏链路、异常分支、资源依赖和风险点
- 希望明确要求代码调整，并把证据充分的修改沉淀为待确认候选变更
- 希望围绕整张图、当前节点或当前步骤发起多轮问题分析

常见使用方式：

1. 选中一个节点、步骤，或直接以当前图为范围
2. 打开 `问答` Tab
3. 选择问答模式，默认保持 `Auto`
4. 在统一输入框中继续提问
5. 打开 `请求` 页核对请求模式、实际模式、提示词、实际附带源码和取证轨迹
6. 查看会话消息、“待确认变更”和“风险线索”
7. 对证据充分的候选变更逐条确认写入草稿层
8. 对证据不足但值得继续追问的风险线索，点击“继续取证”

问答模式含义：

- `Auto`：默认模式，由后端根据问题和风险线程来源识别实际流程。
- `只回答`：用于解释和事实问答，只返回回答、证据、源码上下文和告警，不推进候选变更或风险线程。
- `审计风险`：用于找风险和证据缺口，允许产生风险线程，但不会自动推进草稿候选。
- `代码调整`：用于明确要求修改、修复或生成候选变更，只有证据充分时才保留候选变更。
- 风险线程里的“继续取证”不使用输入框模式，会固定按风险线程取证流程执行。

请求页中的“查看提示词”只有在后端回传提示词内容或提示词 Artifact 时才显示。点击后会展示本轮完整提示词；如果后端只回传 Artifact ID，前端会先请求对应 Artifact 再显示内容。

### 草稿

适用场景：

- 希望沉淀已经确认的业务修改
- 希望把讲解中的说明项和问答中的确认项统一保存
- 希望在生成实现建议和代码 diff 前先确认“业务真相层”

常见使用方式：

1. 打开 `草稿` Tab
2. 查看上半区的草稿变更项和下半区的草稿说明项
3. 默认看修改后视图，需要时切换前后对比
4. 确认草稿内容后再继续生成实现建议或代码 diff

### 实现建议

适用场景：

- 已经确认草稿层，想先形成可执行的改动大纲
- 希望在生成代码 diff 前先看实现层面的建议

常见使用方式：

1. 打开 `草稿` Tab，或从工具栏触发“生成实现建议”
2. 查看实现建议摘要、风险等级和目标文件建议
3. 确认建议是否符合你的预期

### 代码 diff

适用场景：

- 已经接受当前实现建议，想继续得到可写回的 diff 结果
- 希望基于已确认草稿层生成初版代码改动

常见使用方式：

1. 先确认草稿层
2. 再生成实现建议
3. 打开 `代码` Tab，触发代码 diff 生成
4. 先查看文件级 diff、目标路径、结构化改写摘要和风险提示
5. 按需执行“写入全部”或单条写入
6. 需要人工复核时，可直接打开目标文件

## 源码跳转

如果某个节点具有源码位置或可定位签名，可以直接从图中跳回源码。这通常适合：

- 从事实图定位上下游方法
- 从流程图或资源关系视图的投影节点回溯到真实源码节点
- 从资源关系节点定位配置、XML 或 SQL 文件
- 从草稿结果回看目标文件位置

如果不能跳转，通常意味着：

- 当前节点没有足够的位置信息
- 项目索引或主体识别尚未准备好
- 当前节点对应的是说明性或中间性节点，而不是可定位源码实体
- 当前节点不是项目 content root 内的可读源码文件

## 设置入口

设置页主要用于：

- 打开或关闭远程 LLM 相关能力
- 选择具体 LLM 预设
- 配置预设对应的接口、模型和密钥
- 查看当前行为提示

如果你只想使用图分析和本地规则路径，可以不配置远程能力。

## 常见使用建议

- 第一次使用时，先从事实图开始，不要一上来就切到所有高级功能
- 需要理解方法内部流程时，再切到流程图
- 需要核对配置或 SQL 关联时，再看资源关系视图
- Mermaid 更适合做“设计对照”和“同步预览”，不是所有场景都要先导入
- 在执行写回前，先看同步预览、风险提示、实现建议摘要和代码 diff 内容

## 常见问题

### 为什么结果没有走远程 LLM？

常见原因：

- 远程能力没有启用
- 设置未填写完整
- 远程请求失败后回退到了本地规则

这类情况通常会在工作台请求状态里给出说明。

### 为什么图不完整？

常见原因：

- 当前主体边界有限
- 静态分析无法覆盖某些动态路径
- 当前图处于折叠或局部展示状态

这时建议：

- 先切换不同视图核对
- 再检查是否有可展开节点
- 必要时结合讲解步骤、问答会话和草稿层辅助判断

### 为什么不能直接当成代码真相？

因为当前结果本质上是分析与辅助决策产物，不是编译器级真值。尤其是讲解、问答、实现建议和代码 diff 结果，在远程或回退路径下都需要人工复核。
