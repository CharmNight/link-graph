# 使用说明

## 目标读者

这份文档主要面向插件使用者，介绍如何在 IDE 中打开 Link Graph、理解三种视图，并使用 Mermaid、审计、讲解、实现计划和代码草稿等主要功能。

## 打开方式

可以通过以下入口打开 Link Graph：

- 在编辑器中右键，使用链路图相关动作
- 通过工具菜单中的链路图分组打开
- 直接打开右侧工具窗口中的链路图面板

如果当前主体可被识别，插件会围绕当前方法或当前资源加载图数据。

## 界面概览

Link Graph 的工作台通常包含以下区域：

- 顶部工具栏
  - 用于切换视图、导入或导出 Mermaid、查看差异、生成计划、生成讲解和打开设置。
- 主图区域
  - 展示事实图、流程图或资源关系视图。
- 右侧或侧边信息区域
  - 展示当前选中节点的摘要、属性和相关动作。
- 底部结果区域
  - 展示审计、讲解、实现计划、代码草稿、同步预览和差异结果。

## 三种视图怎么用

### 事实图

适合回答“当前方法和上下游依赖是什么”。

推荐用法：

- 从当前方法打开事实图，先看主体与上下游关系
- 通过节点选择、展开和折叠控制阅读范围
- 当你需要定位某个调用链节点时，直接从这里跳回源码

### 流程图

适合回答“当前方法内部的执行步骤和控制流是什么”。

推荐用法：

- 在事实图确认主体后切到流程图
- 用它阅读主要步骤、分支、合流和终止路径
- 当你关注方法内部条件分支或关键流程节点时，优先看流程图

### 资源关系视图

适合回答“代码和资源文件之间有什么连接”。

推荐用法：

- 查看代码与 XML、SQL、配置、文档等资源之间的关系
- 当你怀疑链路跨越配置、Mapper、SQL 或资源文件时，切到这一视图核对

## Mermaid 相关功能

### 导入 Mermaid

适用场景：

- 已经有一份设计草图，希望和当前工作图对照
- 希望从 Mermaid 文本开始补图或做同步分析

使用方式：

1. 点击工具栏或菜单中的“导入 Mermaid”
2. 粘贴 Mermaid 文本
3. 确认导入结果和校验问题

### 导出 Mermaid

适用场景：

- 想把当前图分享给他人
- 想作为设计评审或后续修改的基础文本

使用方式：

1. 点击“导出 Mermaid”
2. 查看生成结果
3. 复制或保存导出的 Mermaid 内容

### 差异与同步预览

当你已经导入 Mermaid，并且当前工作图也存在时，可以继续查看差异和同步预览。这个流程适合用来回答：

- 设计图和现状代码图差在哪
- 如果按设计调整，预计会改哪些节点或关系

## 审计、讲解、实现计划和代码草稿

### 审计

适用场景：

- 希望找遗漏链路、异常分支、资源依赖和风险点
- 希望围绕整张图、当前节点或选中范围发起问题分析

常见使用方式：

1. 选中一个节点，或直接以当前图为范围
2. 点击审计入口
3. 输入问题，等待结果返回
4. 查看结果、证据、风险提示和草稿预览

### 讲解

适用场景：

- 需要快速理解当前链路
- 希望把图和源码片段整理成可读说明

常见使用方式：

1. 打开讲解入口
2. 根据需要填写偏好或关注点
3. 查看生成的摘要、分段说明和警告信息

### 实现计划

适用场景：

- 已经有当前图和差异结果，想先形成可执行的改动大纲
- 希望在生成代码草稿前先看计划层面的建议

常见使用方式：

1. 点击“生成计划”
2. 查看计划摘要、风险等级和目标文件建议
3. 确认计划是否符合你的预期

### 代码草稿

适用场景：

- 已经接受当前计划，想继续得到可写回的草稿结果
- 希望基于当前图和计划生成初版代码结构

常见使用方式：

1. 先生成计划
2. 再触发代码草稿生成
3. 查看生成内容、目标路径和风险提示
4. 决定是否写回项目

## 源码跳转

如果某个节点具有源码位置或可定位签名，可以直接从图中跳回源码。这通常适合：

- 从事实图定位上下游方法
- 从资源关系节点定位配置、XML 或 SQL 文件
- 从草稿结果回看目标文件位置

如果不能跳转，通常意味着：

- 当前节点没有足够的位置信息
- 项目索引或主体识别尚未准备好
- 当前节点对应的是说明性或中间性节点，而不是可定位源码实体

## 设置入口

设置页主要用于：

- 打开或关闭远程 LLM 相关能力
- 配置远程接口、模型和密钥
- 查看当前行为提示

如果你只想使用图分析和本地规则路径，可以不配置远程能力。

## 常见使用建议

- 第一次使用时，先从事实图开始，不要一上来就切到所有高级功能
- 需要理解方法内部流程时，再切到流程图
- 需要核对配置或 SQL 关联时，再看资源关系视图
- Mermaid 更适合做“设计对照”和“同步预览”，不是所有场景都要先导入
- 在执行写回前，先看同步预览、风险提示和代码草稿内容

## 常见问题

### 为什么结果没有走远程 LLM？

常见原因：

- 远程能力没有启用
- 设置未填写完整
- 远程请求失败后回退到了本地规则

这类情况通常会在结果面板或请求状态里给出说明。

### 为什么图不完整？

常见原因：

- 当前主体边界有限
- 静态分析无法覆盖某些动态路径
- 当前图处于折叠或局部展示状态

这时建议：

- 先切换不同视图核对
- 再检查是否有可展开节点
- 必要时结合审计或讲解结果辅助判断

### 为什么不能直接当成代码真相？

因为当前结果本质上是分析与辅助决策产物，不是编译器级真值。尤其是审计、讲解、计划和代码草稿结果，在远程或回退路径下都需要人工复核。
