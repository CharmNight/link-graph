# 调用方法展开设计

## 背景

当前项目已经可以展示事实图、流程图和资源关系图。以流程图为例，`a()` 中调用 `systemService.createInfo()` 时，画布目前只展示一个调用节点。用户可以知道这里发生了调用，但不能在当前链路图里继续检查 `createInfo()` 的内部流程，也不能把被调方法的内部结构合入当前图。

项目已有源码导航、方法签名定位、语义分析、图状态刷新、前端 bridge 和右键菜单基础。缺少的是一个围绕调用节点的增量分析能力：由用户显式选择某个调用节点，后端解析被调方法，将分析结果作为可追踪的展开批次合入当前工作图，并提供对称的批次移除能力。

## 目标

- 在调用节点上提供用户可选择的入口：查看详情、打开源码、展开被调方法。
- 展开被调方法时，不替换当前图，而是将目标方法的内部流程和必要关系合入当前 `workspaceGraph`。
- 每次展开形成一个可追踪批次，后续可通过“移除此展开”整体删除。
- 移除展开时，即使展开出的节点或边后续被用户手工编辑过，也按该展开批次删除。
- 解析不到真实目标方法时不创建猜测节点，只给出明确反馈。

## 非目标

- 不默认递归展开所有下游调用。
- 不引入 LLM 参与目标方法解析或图合并。
- 不在首版解决动态代理、反射、框架回调等无法由 PSI 稳定证明的目标推断。
- 不把普通“删除节点及子节点”改造成展开撤销；展开撤销是独立语义。

## 交互设计

调用节点右键菜单保留并扩展为三个明确动作：

1. `查看详情`
   打开现有节点详情面板，展示标题、签名、来源、metadata、展开状态等信息，不修改图。

2. `打开源码`
   复用现有源码导航能力，跳转到被调方法源码，不修改图。

3. `展开被调方法`
   后端按调用节点 `signature` 定位真实方法，执行语义分析，并将目标方法内部图结构合入当前图。

展开完成后，在展开根节点或展开产生的节点上提供：

- `移除此展开`
  按展开批次删除节点和边。只要节点或边带有该批次 `expansionId`，就删除，即使它后续被手工编辑过。
- `打开源码`
  继续可跳转到对应源码。
- 普通 `删除节点` / `删除节点及子节点`
  继续保留为手工编辑动作，不替代批次移除。

## 后端设计

新增 `InvocationExpansionWorkflow`，作为独立工作流接入 `GraphEditorApplicationService`。它不复用“加载当前方法链路”的状态替换逻辑，而是执行增量合并。

新增 bridge 命令：

- `requestExpandInvocation(nodeId: String)`
- `requestRemoveInvocationExpansion(expansionId: String)`

展开流程：

1. 前端传入调用节点 `nodeId`。
2. 后端从 `trustedNavigationNodes`、当前视图和 `workspaceGraph` 查找节点。
3. 校验节点可展开：
   - `node.type == FLOW_ACTION`
   - `node.metadata["flow.kind"] == "INVOCATION"`
   - `node.signature` 非空
4. 用现有签名定位能力解析为 `CodeSubjectHandle`。
5. 对目标方法执行 `semanticAnalyzer.analyze(...)`。
6. 使用当前投影预算生成目标方法 `AnalysisOutcome`。
7. 将目标方法 `fullGraph` 合入当前 `workspaceGraph`。
8. 新增或补齐从原调用节点到目标方法入口的连接边。
9. 发出 `WorkspaceGraphChanged`，让现有状态通道重新构建事实图、流程图和资源关系图。

## 展开批次元数据

展开产生的新增节点和新增边写入以下 metadata。这些 metadata 表示“由本次展开创建并归属本批次”，用于后续批次移除。

- `linkGraph.expansion.id`
- `linkGraph.expansion.rootNodeId`
- `linkGraph.expansion.sourceInvocationNodeId`
- `linkGraph.expansion.targetSignature`
- `linkGraph.expansion.createdAt`

如果合并时复用已有节点或已有边，不给它写入 `linkGraph.expansion.id`，避免移除展开时误删展开前已经存在的内容。首版只把本次新建的节点、新建的边以及原调用节点到被调方法入口的新连接边标记为该批次归属。

## 合并规则

- 节点去重优先按节点 ID，其次按稳定方法签名。
- 边去重优先按边 ID，其次按起点、终点、类型和 label。
- 展开图中的目标方法入口节点必须可从被调方法签名定位；定位失败则整次展开失败。
- 原调用节点到被调方法入口之间新增一条连接边，用于表达“此调用已展开到目标方法”。这条边也归属该展开批次。
- 如果目标方法入口节点在展开前已经存在，则复用该节点；移除此展开时只删除本次新增的连接边和本次新增的内部节点/边，不删除这个既有入口节点。
- 合并不修改 `selectedMethodSignature`，当前图仍围绕原主体阅读；只更新选中节点和布局所需状态。

## 移除规则

`requestRemoveInvocationExpansion(expansionId)` 按批次执行删除：

- 删除 metadata 中 `linkGraph.expansion.id == expansionId` 的节点。
- 删除 metadata 中 `linkGraph.expansion.id == expansionId` 的边。
- 删除所有连接到已删除节点的边。
- 即使节点或边后续被用户手工编辑过，只要仍带该 `expansionId`，也删除。
- 不删除没有该 `expansionId` 的共享节点。
- 不删除展开前已经存在、只是被本次展开复用的节点。

如果找不到该 `expansionId`，后端给出 warning feedback，不改图。

## 前端设计

前端新增 API 包装：

- `requestExpandInvocation(nodeId)`
- `requestRemoveInvocationExpansion(expansionId)`

流程图和事实图节点菜单根据节点状态显示动作：

- 可展开调用节点显示 `展开被调方法`。
- 带 `linkGraph.expansion.id` 的节点显示 `移除此展开`。
- `打开源码` 继续沿用现有 `requestSourceNavigation`。

节点详情面板增加展开批次展示：

- 目标签名
- 来源调用节点
- 批次 ID
- 可移除入口

## 错误处理

- 节点不存在：提示“未找到需要展开的调用节点”。
- 节点不是调用节点：提示“当前节点不是可展开的方法调用”。
- 缺少签名：提示“当前调用节点缺少目标方法签名，无法展开”。
- 目标方法无法定位：提示“未在当前项目中找到方法：<signature>”。
- 项目正在索引：沿用 smart mode 延迟执行或提示等待索引完成。
- 分析失败：记录日志，并反馈失败原因。
- 工作区版本冲突：丢弃本次结果并提示用户重试，避免覆盖较新的图编辑。

## 测试范围

后端单元测试：

- 调用节点校验：非调用节点、缺签名、目标方法不存在。
- 合并规则：新增节点边、复用同签名节点、连接边生成、metadata 写入。
- 移除规则：按 `expansionId` 删除、手工编辑后仍删除、不删除无归属共享节点。
- 工作区版本冲突不覆盖新状态。

前端测试：

- 调用节点菜单显示 `展开被调方法`。
- 展开批次节点菜单显示 `移除此展开`。
- `打开源码` 与 `展开被调方法` 是两个独立动作。
- 移除展开调用正确 bridge API。

集成或平台测试：

- 从流程图调用节点展开真实 Java 方法。
- 展开后可在图中看到被调方法内部流程。
- 移除展开后图恢复为不含该批次内容的状态。

## 验收标准

- 用户可以在 `systemService.createInfo()` 这类调用节点上选择展开被调方法。
- 展开成功后，当前图保留原主体上下文，并新增被调方法内部流程。
- 用户可以跳转到被调方法源码。
- 用户可以按展开批次移除新增内容。
- 移除展开时，即使展开节点被编辑过，也会按批次删除。
- 无法解析的调用不会创建不可信节点，并给出明确反馈。
